# unslop

글 한 편에 세 스킬을 순서대로 적용하고, 단계마다 멈추지 않고 끝까지 실행한다. 사용자는 마지막에 원문 대비 diff만 본다. 의미, 사실, 수치는 바꾸지 않는다.

## 1. 입력

- 인자가 존재하는 파일 경로이면 읽고, 원본 사본을 scratchpad에 `unslop-original.md`로 저장한다. 결과는 마지막에 같은 경로에 덮어쓴다.
- 아니면 인자 전체를 텍스트로 본다. 비어 있으면 처리할 글이나 경로를 묻고 멈춘다.
- 코드 블록과 인라인 코드를 뺀 본문에서 한글이 글자의 절반 이상이면 한국어 문서, 아니면 영어 문서로 본다.
- 어느 단계에서도 바꾸지 않는 것: 코드 블록, 인라인 코드, URL, 식별자, 커밋 해시, 수치, 날짜, 고유명사, 인용문, 마크다운 헤딩 구조.
- 원본의 코드 블록을 따로 뽑아 둔다. 5단계에서 결과와 비교한다.

```bash
awk '/^```/{f=!f;print;next} f' <원본 사본> > <scratchpad>/code-original.txt
```

## 2. writing-clarity

`Skill("writing-clarity")`로 작업 글을 다듬는다. 주장을 먼저 두고, 지시어가 가리키는 대상과 논리 연결을 분명히 하고, 독자가 제기하지 않은 대비("X가 아니라 Y")를 걷어 낸다. 문장 구조를 바꾸는 단계라서 가장 먼저 돌린다.

## 3. humanize-korean (한국어 문서만)

`Skill("humanize-korean:humanize-korean")`을 fast 모드로 호출한다. 작업 글 본문과 함께 `장르: 리포트`를 넘겨서 장르 추정에 시간을 쓰지 않게 한다. 글이 8,000자를 넘으면 이 스킬이 strict 모드(5인 파이프라인)로 올라가 오래 걸리므로, 시작할 때 사용자에게 한 줄로 알린다.

결과는 현재 작업 디렉터리의 `_workspace/{run_id}/`에 생긴다.

1. `final.md`를 읽는다. 끝에 `<!-- HUMANIZE-SUMMARY ... -->` 주석이 있으면 떼어 낸 본문을 작업 글로 채택한다. 변경률과 등급은 그 주석이나 같은 폴더의 `summary.md`에서 읽어 기록한다.
2. 이번 실행이 만든 `_workspace/{run_id}/`를 삭제한다. `_workspace/`가 비면 그것도 삭제한다. 사용자 저장소에 파일을 남기지 않는다.
3. 변경률이 50%를 넘거나 등급이 D이면 이 단계 결과를 버리고 직전 글을 유지한다. 요약에 그 사실을 적는다.

영어 문서에서는 이 단계를 건너뛴다.

## 4. humanizer

`Skill("humanizer")`를 호출하면서 범위를 지시한다.

- 한국어 문서: 언어와 무관한 서식·문장부호 패턴만 적용한다. 대상은 humanizer의 #14 em/en dash, #15 볼드 남용, #16 인라인 헤더 리스트, #18 이모지, #19 곧은 따옴표, #29 단편 헤딩이다. 한글 어휘와 문체는 고치지 않는다. humanize-korean이 이미 다뤘다.
- 영어 문서: 전체 패턴을 적용한다.
- 두 경우 모두 humanizer의 "PERSONALITY AND SOUL"과 Voice Calibration은 적용하지 않는다. PR과 보고서는 작성자가 하지 않은 의견이나 말투가 더해지면 안 된다.
- humanizer는 초안, "아직 AI 같은 점" 목록, 최종본을 내놓는다. 최종본만 작업 글로 채택하고 나머지는 사용자에게 보이지 않는다.

같은 호출에서 아래 다섯 규칙도 적용하게 한다. `pstack:unslop`에서 옮긴 것이며, 그 스킬은 직접 호출할 수 없어서 여기에 적어 둔다.

- **dash 대체**: em dash는 마침표나 쉼표로만 바꾼다. 괄호, en dash, 하이픈으로 바꾸지 않는다. `구독(subscription)`처럼 용어 옆에 영문을 적는 괄호는 유지한다.
- **문장 중간 콜론**: 목록이나 예시 앞이 아닌 자리에서 연결어처럼 쓴 콜론을 문장 구조로 풀어 쓴다.
- **추상 은유 명사**: surface, vector, wedge, north star, flywheel 같은 말을 구체적인 단어로 바꾼다.
- **느낌 대신 동작**: "DB가 가까이 있다"처럼 느낌만 전하는 문장은 그 문장이 알려 주는 동작이나 수치로 바꾼다. 바꿀 사실이 글에 없으면 지어내지 말고 문장을 지운다.
- **과압축 풀기**: 본문 문장 속 `→`, 동사 없는 조각, 약어를 완전한 문장으로 풀어 쓴다. 코드 블록, 표, 다이어그램 안의 화살표는 그대로 둔다.

## 5. 검사 (건너뛰지 않는다)

두 검사를 모두 통과해야 6단계로 넘어간다.

**코드 블록 보존.** 결과의 코드 블록을 1단계에서 뽑아 둔 것과 비교한다. 다르면 원본 블록으로 되돌리고 다시 비교한다.

```bash
awk '/^```/{f=!f;print;next} f' <작업파일> | diff - <scratchpad>/code-original.txt
```

**문장부호.** 코드 블록 밖에서 em/en dash와 공백 낀 ` -- `를 찾는다.

```bash
awk '/^```/{f=!f;next} !f && /—|–|[^ ] -- [^ ]/{print NR": "$0}' <작업파일>
```

한 건이라도 나오면 각 위치를 문맥에 맞게 마침표, 쉼표, 문장 재구성 순으로 고치고 다시 센다. 0건이 될 때까지 반복한다. 마크다운 수평선 `---`, CLI 플래그 `--flag`, 화살표 `→`는 검사 대상이 아니다.

## 6. 출력

- 파일: 작업 글을 원래 경로에 쓰고 `diff -u <원본 사본> <원래 경로>`를 보여 준다.
- 텍스트: 결과 본문을 그대로 출력한다.

마지막에 단계별 한 줄 요약을 붙인다.

```
writing-clarity: <가장 큰 수정 한 줄>
humanize-korean: 변경률 X%, 등급 Y (영어 문서면 "건너뜀")
humanizer: 수정 N건
검사: 코드 블록 동일, dash 0건
```

## 의존 스킬이 없을 때

`writing-clarity`, `humanize-korean:humanize-korean`, `humanizer` 중 호출에 실패한 것이 있으면 그 단계만 건너뛰고 요약에 "건너뜀(미설치)"으로 적는다. humanize-korean은 `/plugin marketplace add epoko77-ai/im-not-ai` 후 `/plugin install humanize-korean@im-not-ai`로 설치한다.

## 금지선

- 사실, 수치, 고유명사, 인용을 추가하거나 바꾸지 않는다.
- 단계 사이에 사용자에게 승인을 묻지 않는다.
- 파일을 덮어쓴 뒤에도 `git add`, `git commit`, `git push`는 하지 않는다.
